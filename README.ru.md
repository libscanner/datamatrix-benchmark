# Чтение DataMatrix на синтетических кадрах с конвейера

[English version](README.md)

Открытое воспроизводимое сравнение четырёх библиотек чтения DataMatrix (ECC 200)
на 1368 синтетических кадрах, похожих на кадры камеры над конвейером: мелкий
модуль, любой поворот, размытие, наклон, повреждения, изогнутые и мятые
этикетки. Здесь выложены все кадры, ожидаемая строка каждого кадра, генератор
и программы замера — любую цифру можно проверить и дополнить.

| Библиотека | Версия |
|---|---|
| dmr — [DataMatrix Reader](https://github.com/libscanner/datamatrix-reader) (наша) | 1.0.7 |
| [zxing-cpp](https://github.com/zxing-cpp/zxing-cpp) | 3.1.1 (Python) |
| [ZXing](https://github.com/zxing/zxing) (Java) | 3.5.4 |
| [libdmtx](https://github.com/dmtx/libdmtx) | 0.7.8 |

Коммерческие SDK в сравнение не вошли: лицензии большинства из них запрещают
публиковать результаты замеров без согласия производителя.

## Результаты

| Библиотека | Прочитано из 1368 | Ложных чтений | Медиана времени на кадр |
|---|---:|---:|---:|
| **dmr 1.0.7** | **1126 (82,3 %)** | 0 | 5,7 мс |
| zxing-cpp | 955 (69,8 %) | 0 | 1,9 мс |
| libdmtx | 892 (65,2 %) | 0 | 12,1 мс |
| ZXing (Java) | 43 (3,1 %) | 0 | 0,8 мс |

**Прочитано** — строка совпала с закодированной; **ложное чтение** — выдана
другая непустая строка. Общая доля зависит от выбранных значений условий;
пределы ниже говорят больше.

Худшее значение условия (от номинала в сторону ухудшения), при котором
библиотека читает не меньше 90 % кадров точки:

| Условие | dmr | zxing-cpp | libdmtx |
|---|---|---|---|
| Размер модуля, пикселей | **1,4** | 2,0 | 2,5 |
| Поворот в плоскости (при 2,5 px/модуль) | **любой** | до 20° | до 30° |
| Расфокус σ, пикселей | **1,8** | 1,5 | 1,2 |
| Смаз, пикселей | **6** | 4 | 5 |
| Шум σ, уровней | 30 | 30 | 10 |
| Контраст печати | **0,05** | 0,12 | 0,12 |
| Сжатие JPEG, качество | 5 | 5 | 10 |
| Наклон плоскости этикетки | 60° | 60° | 50° |
| Растискивание (доля модуля) | **−55 … +70 %** | −30 … +30 % | −30 … +30 % |
| Повреждение области данных | **10 %** | 5 % | 5 % |
| То же у символа без дополнения | 5 % | 5 % | 5 % |
| Изгиб этикетки на цилиндре (дуга) | **180°** | 150° | 60° |
| Волна, модулей | **0,5** | 0,25 | 0 (только плоская) |
| Мятая бумага, модулей | 0,15 | 0,15 | 0 (только плоская) |
| Плёнка со складками и бликами, модулей | 0,25 | 0,25 | 0,25 |
| Инверсия (светлые модули на тёмном) | да | да | да |

Значения dmr для поворота, контраста 0,05, JPEG 5, растискивания и изгиба
180° — край проверенного диапазона, а не измеренный предел. ZXing (Java) в
таблицу не вошёл: он не набирает 90 % ни в одной точке ни одного условия,
даже на номинале — символы меньше примерно 5 пикселей на модуль он не находит.

Кадров, которые читает кто-то из соперников, но не dmr, — 12 (шум σ = 60:
libdmtx 6 из 12, dmr 3; символ без дополнения с повреждением 10 %: zxing-cpp и
libdmtx по 6 из 12, dmr 3). Кадров, которые читает только dmr, — 126. Не читает
никто — 230.

Полные таблицы: [synthetic/results/summary_synth.md](synthetic/results/summary_synth.md),
[per_point.csv](synthetic/results/per_point.csv); результаты каждой библиотеки
по каждому кадру — [synthetic/results/raw](synthetic/results/raw).

## Как устроен набор и как мерили

Описание набора, методики, инструкция по повтору и оговорки — в
[английской версии](README.md); коротко:

- кадр 720×540, серый, один код на белой этикетке на сером фоне; номинал —
  4 пикселя на модуль, случайный поворот, контраст 0,85, шум σ = 3; меняется
  одно условие за раз, 12 кадров на точку;
- символы — нашим генератором; на 96 номинальных кадрах без искажений dmr и
  libdmtx читают 96, zxing-cpp — 95, ZXing — 8;
- одинаковый серый буфер в памяти для всех, одно ядро, один поток, лучшие
  настройки «из коробки» без подстройки под кадр;
- ноутбук Intel Core i5-1335U, частота процессора записана для каждого
  прогона.
